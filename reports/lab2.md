# rCore 实验 Lab2报告

## 一、问答题

### 1. 列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

SV39 采用三级页表，每个页表项（PTE）为 8 字节（64 位），其组成如下：

| 位域 | 长度 | 含义 |
| --- | --- | --- |
| bit 0 `V` | 1 | Valid：有效位 |
| bit 1 `R` | 1 | Readable：可读 |
| bit 2 `W` | 1 | Writable：可写 |
| bit 3 `X` | 1 | Executable：可执行 |
| bit 4 `U` | 1 | User：用户态可访问 |
| bit 5 `G` | 1 | Global：全局映射 |
| bit 6 `A` | 1 | Accessed：被访问过 |
| bit 7 `D` | 1 | Dirty：被写入过 |
| bit 8–9 `RSW` | 2 | 保留给操作系统软件使用 |
| bit 10–53 `PPN` | 44 | 物理页号 |
| bit 54–63 | 10 | 保留（必须为 0）|

各标志位作用：
- **V（Valid）**：有效位。`V=0` 表示该页表项无效，硬件访问该页时触发缺页异常；此时其余位被硬件忽略，OS 可复用以记录额外信息。
- **R/W/X（读写执行）**：控制该页的访问权限。三者全为 0 时，该表项表示“指向下一级页表”（用于非叶子节点）。
- **U（User）**：`U=1` 表示用户态（U 态）可访问；`U=0` 表示仅内核态（S 态）可访问，用于隔离内核/用户地址空间。
- **G（Global）**：全局映射位，切换 `satp`（地址空间）时不清除带 G 的 TLB 项，用于 TLB 优化（如 trampoline、内核入口）。
- **A/D（Accessed/Dirty）**：由硬件在访问/写入时自动置位，供 OS 的页面置换算法判断页面是否被使用/修改。
- 补充：RISC-V 规定 `W=1, R=0` 的组合为非法（保留）。

### 2. 哪些异常可能是缺页导致的？

RISC-V S 态异常中，与缺页（页面不存在或无效）相关的异常码：

- **Instruction Page Fault**（异常码 12）：取指时缺页。
- **Load Page Fault**（异常码 13）：读内存时缺页。
- **Store/AMO Page Fault**（异常码 15）：写内存（含原子操作）时缺页。

（访问类异常如 Load Access Fault（码 5）、Store Access Fault（码 7）属于物理访问错误，与“页面不在页表/无效”的缺页在含义上有所区别，本实验的 trap 处理统一将其按页错误杀死进程处理。）

### 3. 发生缺页时，描述相关重要寄存器的值

（通用寄存器保存于 trap context，上次实验已详述，这里简略。）

- **sepc**：触发缺页的那条指令的地址（异常返回后需要跳回此处重新执行）。
- **stval**：发生缺页的虚拟地址。对取指/读/写缺页，`stval` 保存引发异常的虚拟地址，是判断缺页落在哪个地址区间的关键。
- **scause**：异常原因寄存器。其 interrupt 位区分中断/异常，exception code 区分缺页类型（12/13/15）。
- **satp**：当前页表的根（含 SV39 模式位），用于定位是哪个进程的页表。

### 4. Lazy 策略的好处

- **缩短启动延迟**：程序加载时不必一次性为所有段分配物理内存并做页表操作，启动更快。
- **节省物理内存**：只为真正被访问的页分配物理帧，很多程序实际只会用到映射空间的一小部分。
- **减少 I/O**：从未被访问的段不需要从磁盘读入，省去无效的磁盘加载。
- **支持内存超售（overcommit）**：虚拟地址空间可以远大于物理内存，只有被访问的页才占用物理帧。
- **避免无意义的页表操作**：例如 mmap 申请大量内存但只使用其中一小部分，避免了大量没用的页表建立/拆除。

### 5. 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存？（估算数量级）

SV39 为三级页表：页大小 4KB（2^12），每级表 512（2^9）项、每项 8 字节，故每个页表页 4KB。

10G = 10 × 2^30 字节 → 需要映射的叶子页数为 `10×2^30 / 2^12 = 10×2^18` 个。

- 叶子级（第 1 级）页表页数：`10×2^18 / 512 = 10×2^9 = 5120` 页
- 中间级（第 2 级）：`5120 / 512 = 10` 页
- 根级（第 3 级）：1 页

合计约 `5120 + 10 + 1 ≈ 5131` 个页表页，约 `5131 × 4KB ≈ 20 MB`。

**数量级：约 20 MB（2^24 量级），即约 5000 个页表页。**

### 6. 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？

**实现思路**：在 mmap / 加载程序段时，只把“虚拟地址区间 + 权限”记录在元数据中（类似 `areas` 列表），**不实际分配物理帧、不在页表中建立有效映射**（或建立后即置 V=0）。

**缺页处理**：
1. 从 trap context 中取出 `stval`（触发地址）和 `sepc`（指令地址）。
2. 判断 `stval` 是否落在某个已登记但尚未实际分配的区间内：
   - 若不在 → 非法访问，杀死进程；
   - 若在 → 为该页分配一个物理帧，按记录的权限建立页表映射，并把该页标记为“已分配”，随后返回用户态重新执行触发指令（`sepc` 无需修改）。
3. 已分配页面再次缺页则按正常缺页处理（或换入/换出）。

### 7. 缺页的另一个常见原因是 swap 策略，此时页面失效如何表现在页表项（PTE）上？

页面被换出到磁盘后，将该页对应 PTE 的 **V 位置 0（无效）**，硬件访问该页时即触发缺页异常。由于 `V=0` 时硬件忽略其余位，OS 可以**复用 PTE 的空闲位**（如 `RSW` 位或 `PPN` 位域）记录该页在磁盘上的位置（换出目标块号/偏移），供缺页处理时换入定位。同时，`A`/`D` 位反映页面是否被访问/修改，可作为页面置换算法选择换出页的依据（优先换出“久未访问且未修改”的页）。

### 8. 在单页表情况下，如何更换页表？

将新页表根物理页号连同 SV39 模式位（`satp` 高 4 位为 8，`8 << 60 | root_ppn`）写入 `satp` CSR，然后执行 `sfence.vma` 刷新 TLB 即可。进行进程切换时，对要切换到的每个进程的页表执行上述写 `satp` + `sfence.vma` 操作。

### 9. 单页表情况下，如何控制用户态无法访问内核页面？

利用 PTE 的 **U 标志位**：将内核页面映射为 `U=0`（仅 S 态可访问），用户页面映射为 `U=1`。用户态访问 `U=0` 的页面时会触发权限异常，从而保证用户态无法访问内核页面。（与上一题“最后一问”一致：U 位机制即权限隔离的关键。）

### 10. 单页表有何优势？

- **系统调用/陷入开销低**：陷入内核时无需切换页表（内核态复用当前进程页表），省去 `satp` 切换与 `sfence.vma` 的 TLB 刷新开销。
- **用户指针翻译简单**：内核与用户共用一张页表，内核可直接访问用户缓冲区，无需在两张页表间往返翻译系统调用参数。
- **TLB 抖动小**：不需要频繁切换地址空间，TLB 命中率更高。
- **实现更简单**：无需维护独立内核页表及两套地址空间的切换逻辑。

### 11. 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表？

- **双页表**：内核拥有独立页表（`KERNEL_SPACE`），每个进程拥有自己的用户页表。因此：
  - **每次陷入内核（trap 入口）**时，从用户页表切换到内核页表；
  - **每次返回用户态（trap 返回）**时，切回当前进程的用户页表；
  - **切换进程**时，切换到新任务的用户页表。
- **单页表操作系统**：因为内核与用户共用一张页表，**只在进程上下文切换（切到另一任务）时**才更换 `satp` 为该任务的页表；系统调用陷入/返回内核态时无需更换页表（内核态复用当前进程页表）。
